[6 #36740CAA @2] 1. TeMFpy (Python, 1D — the most direct answer)
[7 #7189051E @FirstParagraph] TeMFpy (Hille & Szabó, 2025) is a library built on TeNPy that converts fermionic mean-field states — both Slater determinants and Pfaffian (Bogoliubov/BCS-type Gaussian) states — into finite or infinite MPS form, and it explicitly includes a Gutzwiller projection facility (temfpy.gutzwiller, e.g. abrikosov_ph() for Abrikosov-fermion spin-liquid constructions). Once both projected states are MPS, the overlap ⟨Ψ₁|Ψ₂⟩ is just a standard exact MPS contraction — so this package covers both halves of your question. It’s on PyPI (pip install temfpy) and MIT-licensed.
 └ cstyle=VerbatimChar;hAnsi=Consolas;latin=Consolas;size=11pt "temfp…ller" · cstyle=VerbatimChar;hAnsi=Consolas;latin=Consolas;size=11pt "abrik…ph()" · cstyle=VerbatimChar;hAnsi=Consolas;latin=Consolas;size=11pt "pip i…mfpy"
[8 #622A86FE @a0] Caveat: MPS is inherently a 1D (or quasi-1D/cylinder) representation, so this is the right tool for chains and ladders, not 2D thermodynamic lattices.
[9 !bookmarkEnd id=20]
[10 !bookmarkStart mvmc-c-any-dimension-monte-carlo id=21]
[11 #60E8944E @2] 2. mVMC (C, any dimension — Monte Carlo)
[12 #1E6B5BB4 @FirstParagraph] If you want Gutzwiller-projected BCS/Pfaffian wave functions in 2D or 3D, mVMC (Misawa et al.) natively implements the fully projected (g→∞) Gutzwiller wave function and evaluates its amplitudes via Pfaffians. It also explicitly supports computing overlaps between two different optimized variational wave functions (the standard tool for excited-state/nodal-surface calculations). This gives you the overlap, but as a statistical Monte Carlo estimate rather than an exact number.
 └ +b "mVMC" · +i "different"

[15 #757FA2A8 @2] 3. Research codes (not packaged, but adaptable)
[16 #7DC2AC3E @Compact list=1001.L0] QSpace-based codes for the U(1)-GfPEPS construction of Li, van Delft & Tu, where Gutzwiller projection is applied as a product of local operators and projected Dirac spin-liquid states are contracted with CTMRG — this is a PEPS (2D) route, but the code is research-grade, not a library.

[17 #792B9FAE @Compact list=1001.L0] The MPO–MPS method (Wu et al.; Liu, Tu et al.) converts Gutzwiller-projected paired fermion states to MPS by applying Bogoliubov-quasiparticle MPOs to the vacuum; projection is a D=1 MPO applied afterward. [20 #6ECD1332 @2] One theoretical caveat worth knowing
[21 #3C1538EE @FirstParagraph] For unprojected Gaussian states, the overlap is a single Pfaffian/determinant (Balian–Brézin / Onishi formula), which TeMFpy uses internally for its fast overlap routines. For projected states there is no equally universal closed form — the overlap becomes a sum over particle-number/spin sectors, which is exactly why people either go through MPS (exact, 1D) or Monte Carlo (any dimension). In special 1D cases (Jordan–Wigner-solvable paired states), recent work does derive exact Pfaffian formulas for projected-state overlaps.

[38 #49B1146C @2] The algorithm
[39 #7F41F470 @FirstParagraph] Setup. Represent each Gaussian state by its matrix: - Slater determinant: the N_σ × N_s coefficient matrix U (per spin, or 2N×2N block for paired orbitals); - General paired (BCS) Gaussian state: the antisymmetric 2N_s × 2N_s matrix Z in |Ψ⟩ = exp(½ Σ Z_ij c_i† c_j†)|0⟩.
 └ +b "Setup."
@range [40–43] @a0 (range facts apply to every block in the range and are not repeated on block lines; same below)
[40 #70193264] Amplitudes. For any configuration c (a set of occupied modes), the unprojected amplitude is a minor: - Slater: ⟨c|Ψ⟩ = det U_c (submatrix of occupied rows) - BCS: ⟨c|Ψ⟩ = Pf(Z_cc) (2n×2n submatrix; n = number of pairs)
 └ +b "Amplitudes."
[41 #6E7E151C] Both are O(n³) per configuration — this is the standard fermionic-Gaussian “fidelity” trick, and it’s exactly the machinery TeMFpy uses internally.
[42 #57BBB53A] Projection + overlap. The projected overlap is just a weighted sum over the surviving configurations:

[82 #3934C50E @2] What’s a reasonable m for 4×4?
@range [83–85] @Compact list=1005.L0
[83 #3E78BBC0] m ≤ 3 (spinless) or m = 1 (spinful): exact enumeration is clearly the right method — minutes at worst, exact, no approximations.
 └ +b "m ≤ 3…thod"
[84 #0F5B36A8] m = 4 (spinless) / m = 2 (spinful): the boundary case. Still feasible with a compiled Pfaffian loop + multiprocessing (the enumeration embarrassingly parallel over configurations), but you’re paying real compute. Worth doing if you need exact numbers.
 └ +b "m = 4…ase."
[85 #2CE6F132] m ≥ 5: brute force enumeration breaks down, but at this system size you don’t need it — Metropolis Monte Carlo over the m¹⁶ configurations with weight |A(c)|² will give the overlap to 4–6 significant digits with ~10⁸ samples, because the configuration space is small and well-behaved. [87 !bookmarkStart practical-tips id=31]
[88 #7AC29064 @2] Practical tips
@range [89–92] @Compact list=1006.L0
[89 #6D5A7AB8] The constant factor matters here: don’t loop in pure Python. A Numba-compiled skew-LDL Pfaffian or a small C extension gets you ~10⁶ configs/s; pure Python is ~100× slower and would demote m=3 to “hours.”
[90 #5D1B06CE] Nothing needs to be stored — amplitudes are computed on the fly, so memory is negligible.
[91 #0CAEFE12] Symmetry reduction buys constant factors only: restricting to a momentum sector divides the sum by ~16, and parity/number sectors by 2–4×. Useful at m=4, irrelevant at m=2.
[92 #5E59B894] One caveat: if your filling scales with m rather than being fixed at one particle per cell (e.g., you fill a fraction of the 16m modes), then N_f grows with m and the per-configuration Pfaffian picks up an extra polynomial factor — still secondary compared to the m¹⁶ base, but it softens the “Pfaffian size is constant” statement.
[93 #5AFEF016 @FirstParagraph] Bottom line: exact enumeration comfortably handles up to ~3 orbitals per cell (spinless) on a 4×4 cluster, with 4 as a parallelizable stretch goal; beyond that, Monte Carlo on the same configuration space is the sensible continuation and is effectively exact at this size.
